# Diseñar catalogo de sitios de demostracion

**Para qué sirve:** Estructurar ejemplos visuales vendibles sin confundir demos con clientes reales.

**Campos a personalizar:** `[SECTORES]`, `[IDENTIDAD]`, `[FORMATOS]`, `[FUNCIONES]`

## Prompt listo para copiar

Crea un catálogo de demostraciones de páginas web dirigido a [SECTORES], con identidad visual [IDENTIDAD], formato de entrega [FORMATOS] y funciones permitidas [FUNCIONES].

Propón una ficha por demo con nombre ficticio claramente identificado, público, objetivo, secciones visibles, funciones reales o simuladas (etiquetadas), requisitos, beneficios plausibles y limitaciones. Prioriza ejemplos que se puedan abrir fácilmente en móvil. No presentes demostraciones como trabajos hechos para empresas reales. Indica qué archivos visuales habría que generar y cuáles se produjeron efectivamente.

En cada ficha distingue obligatoriamente **concepto propuesto**, **prototipo o archivo realmente creado y verificado**, **URL navegable comprobada** y **funciones efectivamente implementadas**. Sin archivos o URL accesibles, indica «DEMO NO CREADA — SOLO CONCEPTO», «URL: NO DISPONIBLE» y «FUNCIONES IMPLEMENTADAS: NINGUNA». Un menú, formulario, carrusel, selector de citas u otro control solo puede marcarse «funcional» si fue construido y probado; de lo contrario usa «SIMULACIÓN PROPUESTA, NO OPERATIVA». No atribuyas resultados o beneficios medidos a prototipos no probados.

## Comprobación del resultado

- ¿Se respondió al objetivo y se completaron las tareas autorizadas?
- ¿Se separaron hechos, inferencias y pendientes, sin inventar accesos, fuentes ni acciones?
- ¿El formato final permite usar el resultado directamente?
